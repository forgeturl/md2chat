Markdown 复制到聊天后图片丢失怎么办？

按来源、预览、复制入口和目标输入框逐步排查图片缺失，区分浏览器限制、飞书富文本输入框和企微分段粘贴。

直接回答

先检查 md2chat 预览是否有图，再检查复制目标与粘贴方式。预览缺图要补充可读取的原图；预览有图但聊天里缺图，要按平台使用桌面原生复制或企微分段复制。剪贴板里存在图片引用，不代表目标客户端已导入图片。

预览里已经缺图

核对 Markdown 图片地址是否有效、远程服务是否允许读取，以及原始内容是否实际包含图片。桌面版可导入符合校验的本机图片；网页不能直接读取任意本机文件路径。只有占位文字而没有图片数据时，转换器无法恢复原图。

预览正常，粘贴后只剩文字

钉钉和飞书请使用桌面版；飞书先展开富文本输入框。企业微信有图时逐段复制、粘贴。微信使用标准图文复制，需核对当前系统与客户端。邮件中的内嵌图片还可能被编辑器或收件端移除。

如何提供有用的排查信息？

使用下面的虚构示例重现，记录系统、浏览器或桌面版、md2chat 和目标客户端版本，以及哪一步开始丢图。桌面版可显式读取当前剪贴板并复制脱敏报告。Windows 钉钉图片可能位于专有 JSON 属性中，普通 HTML 图片标签统计为零不能证明没有图片。

怎样验收修复？

分别确认预览、复制、草稿粘贴和发送后结果。先检查下面示例中的开头、表格图片、结尾，再尝试普通文字是否可编辑。只在自己的测试会话验收，避免提供真实工作正文、图片地址或登录信息。

操作步骤

  1. 先用公开示例确认预览中的图片是否完整。
  2. 按目标平台使用对应复制入口和输入框。
  3. 在自己的草稿里核对图片、文字和顺序。
  4. 仍失败时，收集版本号与脱敏报告；最后复制报告，避免覆盖待测剪贴板。
