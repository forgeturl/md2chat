Why do images disappear when pasting Markdown into chat?

Troubleshoot missing images by checking the source, preview, destination copy option and chat input separately.

Content reviewed：2026-10-18

Direct answer

First check whether the image appears in md2chat. If it is missing in the preview, fix the source. If it appears there but disappears in chat, use the destination workflow: desktop for DingTalk and Feishu, expanded input for Feishu, or sequential copies for WeCom.

The preview is missing an image

Check the Markdown URL, source availability and whether the copied content actually included image data. A remote host can restrict access. The web editor cannot read arbitrary local paths. A placeholder is not enough to reconstruct a missing image.

The preview works but chat loses images

Clients choose which clipboard format to import. Standard HTML, a file reference or a PNG combined with text can be treated differently. Try the minimal public example and the platform-specific guide. Email editors and recipients can also remove embedded data-URI images.

Collect useful evidence

Record OS, browser or desktop version, md2chat version, destination version and the first failing step. Use explicit diagnostics with fictional content. Copy the report last because it replaces the clipboard. Windows DingTalk images may live in a JSON attribute rather than ordinary img tags.

Validate the actual outcome

Inspect preview, copy, draft paste and sent result separately. Check the opening text, image and ending, then whether ordinary text is editable. Do not provide private work messages, original image URLs or credentials in a report.

Step by step

  1. Check the public sample in the preview.
  2. Use the destination-specific copy option and input.
  3. Inspect the image count and text order in your own draft.
  4. If it still fails, collect version numbers and a sanitized report.
