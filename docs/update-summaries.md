# 面向用户的更新摘要

应用内默认展示简短摘要，完整技术记录保留在 `docs/release-notes.md` 和 GitHub Release。摘要按版本存于 `docs/releases/<主版本.次版本>/<完整版本>.json`（例如 `docs/releases/0.6/0.6.23.json`），由发布命令与版本、详细记录一起维护。

## 写作规则

- 每个版本用 1～3 条短句介绍用户能感知的变化；每条只说一件事，各语言每条最多 180 个 Unicode 字符。优先说明哪里变了、怎样使用。
- 平台限制和必要操作写清楚。兼容性沿用实际证据；代码生成或自动化检查通过不能写成客户端粘贴已通过。
- 测试数量、内部协议、重构和构建细节写入详细记录。仅内部维护时，摘要可写“本次为内部维护更新，无需调整使用方式”，并补齐译文。
- 摘要与可选 `important` 提醒均须人工编写九种语言：`zh-CN`、`en`、`es`、`pt-BR`、`ja`、`ko`、`de`、`fr`、`hi`。同一字段各语言条数一致、事实和限制一致。应用按当前界面语言选择，不运行在线翻译。
- 必须影响升级决定或操作的事项放入 `important`，例如需要重新配置、功能撤下、导出数据包含原文。提醒在跨版本历史折叠时也始终显示，并注明所属版本。

## 数据与发布

准备版本时，另存一个不带 `version` 的摘要 JSON，例如以下结构（所有语言都必须填写真实译文）：

```text
{
  "summary": {"zh-CN": ["用户能感知的变化。"], "en": ["A user-visible change."], ...其余七种语言},
  "important": {"zh-CN": ["必要提醒。"], "en": ["An essential notice."], ...其余七种语言}
}
```

没有必要提醒时省略整个 `important` 字段。使用 `release:prepare` 的 `--summary-file` 参数；命令自动添加版本，并与详细说明一起原子更新，网络校验失败或检测到并发编辑时保留原文件。

`npm run check`、`release:verify` 和更新清单生成均校验摘要：版本匹配、最新在前、历史完整、九种语言完整、条数和长度合规。历史记录中的失败标签用 `{"version":"0.6.14","unpublished":true}` 明确标记；以发布记录为依据，应用跳过这些版本。正式发布失败后准备后继版本时，先确认未产生公开 Release，再将该失败版本标记为未发布，后继摘要承接其实际变化。

## 发布协议与按需读取

`latest.json` 保持标准 updater 字段：`version`、`notes`、`pub_date`、`platforms`。`notes` 是当前版本的简短中文摘要与提醒，旧版客户端照常读取；安装器签名验证与摘要历史相互独立。

新增可选字段 `releaseNotes`：

```text
{
  "schemaVersion": 1,
  "current": 当前版本的九语摘要和可选提醒,
  "history": {"file": "update-history-v1.json", "bytes": 字节数, "sha256": 内容哈希}
}
```

发布工具自动生成 `update-history-v1.json` 索引和 `update-history-v1-<语言>-<主.次>-<段号>.json` 历史文件；每段覆盖最多 50 个 patch 版本号，例如 `0.6-0` 为 0.6.0～0.6.49，`0.6-1` 为 0.6.50～0.6.99。各文件上传至目标版本的 GitHub Release，纳入发布完整性校验和 `SHA256SUMS.txt`。索引只包含已发布版本、分段与文件描述，不重复摘要内容；主更新清单仅携带当前版本摘要，大小不随完整历史线性增长。

客户端打开更新窗口后，由受限原生命令读取固定仓库、固定目标版本的索引，仅加载与 `当前版本 < 历史版本 ≤ 目标版本` 相交的当前语言分段。不向网络发送正文、语言设置文件或任意用户提供的 URL。每个文件验证预期字节数和 SHA256；索引最多 2 MiB、单分片最多 256 KiB，整次请求最多 30 秒。缓存仅在进程内，随目标版本/索引哈希变化重置，历史分片缓存最多约 4 MiB。

历史全部验证通过后，按版本从新到旧显示，最近 3 个默认可见，其余折叠；跨越版本的必要提醒全部保持可见。语言切换读取对应语言并复用缓存；迟到的其他语言或目标版本响应不会覆盖当前界面，下载进度刷新保留展开状态。

历史未完整加载时，仅显示当前版本摘要与提醒、明确的不完整提示；不显示完整版本数量。关闭后重新打开时重试失败的历史请求；已成功加载的历史复用缓存，仍在加载的请求不重复发起。历史失败、超时或不支持的协议均不阻止下载安装。原始说明及详情链接继续可用，链接固定至目标版本 Release。

兼容顺序：

1. 已发布的旧客户端继续读取 `notes` 与标准 updater 字段，忽略新增字段。
2. 新客户端识别 `releaseNotes.schemaVersion: 1`，遇到旧清单的内嵌 `releases` 仍按旧结构显示。
3. 缺少摘要协议或遇到未知 `schemaVersion` 时，回退到 `notes` 和完整说明链接。已知协议内的未知可选字段忽略，已有字段保持原含义；不兼容变更使用新协议版本。

根据已有详细记录回填的版本仍为 v0.6.1～v0.6.23，v0.6.7、v0.6.10、v0.6.14 标为未发布。旧版客户端安装包含新界面的正式版本后才获得新展示能力，不能将协议测试写成真实跨版本安装通过。

## 更新窗口展示

采用简洁的状态标题、行内版本信息和按版本分组的摘要列表，不再为“发现新版本”展示空心圆或独立灰色状态卡。可下载新版或已下载待安装时，状态标题使用绿色；无新版时使用普通深色。下载页面文字和箭头始终使用绿色。仅检查、下载、安装进行中显示加载图标，并尊重减少动态效果设置。

无新版时仅显示当前版本和再次检查操作，不展示候选版本、升级摘要或安装前保存提醒。标题、版本标签、状态提示、操作、摘要和必要提醒均随界面语言切换，长文案允许换行；窗口较矮时摘要区域滚动，底部操作保持可见。

## 验证

自动检查覆盖版本区间、数字版本排序、历史折叠、重要提醒、九语言切换、纯文本安全渲染、旧清单回退及准备命令的原子写入。浏览器界面验证与真实安装升级分别记录；未执行的跨版本安装不能记为通过。
