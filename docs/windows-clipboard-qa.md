# Windows 剪贴板与钉钉验证

Windows 打包流水线先运行 Rust 原生剪贴板往返测试，再构建 Tauri 安装包。也可单独运行 Actions 的 **Windows clipboard validation**，不触发 Release。自动测试通过不等于钉钉粘贴通过。

## 自动验证

Windows 安装 Node.js 22、Rust 和 Visual Studio C++ 构建工具后，在仓库根目录执行 `npm ci`、`npm run desktop:test:windows`。此命令会临时替换系统剪贴板，完成后恢复；请在不使用剪贴板时运行。失败时退出码非零。

原生测试使用生产 Rust 剪贴板接口写入与读回，检查 HTML / 纯文本、CF_HTML 字节偏移及 PNG 表示。一般模块测试使用 `npm run desktop:test`；触及真实剪贴板的往返测试标记为 ignored，只由明确的原生验证命令执行。

Actions 的 `windows-clipboard-qa`（独立验证）或 `windows-clipboard-qa-release`（发布验证）附件包含原生测试日志、本说明及人工 Markdown 样例。日志不包含原剪贴板正文、图片或地址。自动验证判断系统格式传输和数据完整性，不能判断钉钉是否接受这些表示。旧 Electron 实现及其专用测试已移除，当前验证使用 Rust 原生接口。

## 钉钉人工用例

使用 `examples/windows-clipboard/` 的三个虚构 Markdown 样例：先纯文字，再一张表格图片，再表格与代码两张图片。逐个粘贴进 md2chat；只在自己的钉钉草稿测试，无需发送。结果记录在 `results-template.md`。

1. 点击普通「钉钉」复制，粘贴到钉钉，记录完全空白 / 仅文字 / 完整图文 / 部分图片。当前使用 Chromium 兼容 CF_HTML 并保留纯文本兜底，仍需以钉钉客户端结果为准。
2. 打开「剪贴板排查」，点击「复制 HTML 文字测试」，粘贴到钉钉。记录是否出现 **md2chat HTML 文字测试**。此步骤只写无图 HTML；仍为空时，原因不能只归到本机图片引用。
3. 从钉钉复制一条已有的、可正常粘回的测试图文。先直接粘到草稿确认，重新复制同一条消息，再点「重写当前 HTML」，再次粘贴。它保持读取到的 HTML 文档字符串不变，但原生层会重建 CF_HTML 系统封装；不承诺原生字节不变。原复制成功而重写失败时，应继续查系统表示或客户端附加信息；重写成功后，再查生成结构和图片来源。

每次测试会替换剪贴板。先记录粘贴结果，需要报告时再点「读取当前剪贴板」，最后统一复制报告；中途复制报告、截图或其他消息会替换待测试内容。不需要提供真实工作正文、图片地址或登录信息。

报告里的 `StartFragment 无` 只描述解码后的 HTML，不能说明原生 CF_HTML 头缺失。原生 Rust 测试直接检查该头部；它也不能证明钉钉导入成功。
