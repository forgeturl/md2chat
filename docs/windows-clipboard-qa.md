# Windows 剪贴板与钉钉验证

正式发布会运行 Rust 原生剪贴板往返测试，测试失败会阻止发布。也可单独运行 Actions 的 **Windows clipboard validation**，不触发 Release。自动测试通过不等于钉钉粘贴通过。

## 自动验证

Windows 安装 Node.js 22、Rust 和 Visual Studio C++ 构建工具后，在仓库根目录执行 `npm ci`、`npm run desktop:test:windows`。此命令会临时替换系统剪贴板，完成后恢复；请在不使用剪贴板时运行。失败时退出码非零。

原生测试使用生产 Rust 剪贴板接口写入与读回，检查 HTML / 纯文本、CF_HTML 字节偏移及 PNG 表示。一般模块测试使用 `npm run desktop:test`；触及真实剪贴板的往返测试标记为 ignored，只由明确的原生验证命令执行。

独立 Windows 验证只在 main 的原生剪贴板、图片处理、主窗口与托盘集成，以及相关构建或测试文件变化时自动运行；Mac 专用剪贴板、网页资源、package 和 Cargo 版本文件的变化不会触发。依赖或其他配置调整需要提前验证时，可手动运行；正式版本标签仍执行 Windows 验证。通用 JavaScript 与 SEO 检查由 **Check** 工作流和发布前置检查执行，不在独立 Windows 任务中重复运行；原生测试命令的 prehook 会准备桌面前端。

Actions 的 `windows-clipboard-qa`（独立验证）或 `windows-clipboard-qa-release`（发布验证）附件包含原生测试日志、本说明及人工 Markdown 样例。日志不包含原剪贴板正文、图片或地址。自动验证判断系统格式传输和数据完整性，不能判断钉钉是否接受这些表示。旧 Electron 实现及其专用测试已移除，当前验证使用 Rust 原生接口。

## 钉钉人工用例

使用 `examples/windows-clipboard/` 的三个虚构 Markdown 样例：先纯文字，再一张表格图片，再表格与代码两张图片。逐个粘贴进 md2chat；只在自己的钉钉草稿测试，无需发送。结果记录在 `results-template.md`。

1. 点击普通「钉钉」复制，粘贴到钉钉，记录完全空白 / 仅文字 / 完整图文 / 部分图片。当前使用 Chromium 兼容 CF_HTML 并保留纯文本兜底，仍需以钉钉客户端结果为准。
2. 重新复制 md2chat 的测试结果，打开「剪贴板排查」，点击「读取当前剪贴板」，核对展示的文字、图片和未读取格式，再导出诊断 ZIP。
3. 从钉钉复制同一条已有的测试图文，重新读取并导出另一个 ZIP，对比其中的原始格式和解析结果。每次读取替换当前样本，关闭窗口会清空内容；需要对比时请分别导出。

当前 Windows 钉钉生成路径使用 `data-clipboard-cangjie` JSON 图文树及内嵌 PNG，不再使用 `file:` 图片引用。验收时特别检查“文字—图片—文字—图片—文字”的顺序、两张图片能否显示以及空行是否保留。本机已确认钉钉原始样本仅保留 HTML 重写后可粘贴两张图片；这不等于新构建已通过验收。排查摘要的图片计数仍按普通 HTML 标签统计；诊断 ZIP 的 `.html-details.json` 会解析属性内的 JSON，可进一步核对其中的图片。

每次测试会替换剪贴板。先记录粘贴结果，需要报告时再点「读取当前剪贴板」，每次读取后导出当前样本的诊断 ZIP；导出不会改写剪贴板。中途截图或复制其他消息会替换待测试内容。不需要提供真实工作正文、图片地址或登录信息。

报告里的 `StartFragment 无` 只描述解码后的 HTML，不能说明原生 CF_HTML 头缺失。诊断 ZIP 保留原生 CF_HTML 字节，可直接检查该头部；原生 Rust 测试也会检查它。头部存在不能证明钉钉导入成功。
