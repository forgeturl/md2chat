# 平台能力矩阵与验证记录

本文件记录当前实现、验证范围与后续验收入口。最后更新：2026-10-21。历史客户端证据来自 [兼容性记录](compatibility.md)，不代表本次修改已经在客户端验收。

## 标题规则

- `#` 到 `######` 以及 Setext 标题均移除 Markdown 标记，不自动补 `【】`。原文手写的括号保留。
- 标题独占一行，沿用现有转换的段落间距（相邻标题之间单换行）；各级字号与正文一致。通用预览和转图默认加粗，选择平台复制后的预览采用对应平台策略。
- 微信、Windows 钉钉、网页及 Windows 企微输出普通标题；Mac 钉钉、飞书桌面版、Mac 企微、邮件和图片保留标题粗体。
- 只调整标题加粗，正文显式的粗体、斜体、删除线沿用现有能力。标题内显式的斜体、删除线、链接等仍沿用现有解析规则；不额外放大字号。
- 内部文字 run 的 `heading: 1..6` 标识标题，用于出口适配；普通正文没有该标记。目标私有协议只输出其支持的字段。
- 主窗口、托盘和全局转换快捷键共用 Markdown → segments → 平台出口。转图直接使用含粗体的原始 segments，不继承某次平台复制的降级结果。

## Windows 企微整段图文探针验证

2026-10-21，在 Windows 本机、企业微信 `5.0.12.6018` 的“文件传输助手”普通输入框中测试。仓库基于 `2cbf7f8` / v0.6.23，测试前工作区干净；本次仅补充记录，未改动发送或复制实现。系统具体版本与架构未核实。使用 Windows Forms 写入标准 CF_HTML，再用客户端 Ctrl+V 粘贴；这是独立格式探针，不是 md2chat 新构建验收。

| 检查 | 输入框实测结果 | 自动检查 / 限制 |
| --- | --- | --- |
| 输入框原生复制样本 | 原样粘贴保留前文、图片位置、后文 | 包含 `WeWork Message`（744 字节，带 Boost archive 特征）、`WeChat_RichEdit_Format`（151 字节，XML）、HTML 和 UnicodeText；CF_HTML 偏移、UTF-8、片段标记检查通过；不保存正文和路径到仓库 |
| 原样本仅保留 HTML + UnicodeText | 仍保留前后文字和图片节点 | 从输入框全选复制回读，HTML 中图片数为 1，去标签后的 10 个字符与原片段顺序一致；HTML 和图片引用被客户端重写，不能宣称字节不变；原图接近白色，另用彩色样本验证显示 |
| 自建标准 HTML + 本地 PNG | `WIN-BEFORE` → 蓝绿双色图 → `WIN-AFTER` 完整显示 | 160 × 80 PNG，`file:///` URI；未提供两种企微私有格式，证明该样本的草稿粘贴不要求私有协议；图片在编辑器中显示尺寸缩小 |
| 相同标准 HTML + 内嵌 PNG | 前后文字保留，图片消失 | 仅将图片来源改为 `data:image/png;base64,...`，本机客户端不显示该图片 |

结论：标准 CF_HTML + 可访问的本地 PNG 缓存是 Windows 企微整段图文的候选实现路径。当前产品仍使用分段复制，通用 HTML 图片由 `payload.rs` 生成为 data URI；尚未将本地缓存路径接入 Windows 企微。单独两种私有格式的必要性实验在 HTML 路径成功后未继续，未确认客户端完整格式优先级。

客户端发送后效果、中文/emoji、多图、表格、正文强调、文字编辑、缓存有效期以及产品主窗口/托盘/快捷键整段链路均待验证。此次没有发送消息，没有运行会替换剪贴板的原生测试套件；结束时已恢复原始四格式剪贴板和原草稿。探针脚本、彩色图和原始备份仅位于本机临时目录，未加入仓库。
