# 平台能力矩阵与验证记录

本文件记录当前实现、验证范围与后续验收入口。最后更新：2026-10-20。历史客户端证据来自 [兼容性记录](compatibility.md)，不代表本次修改已经在客户端验收。

## 标题规则

- `#` 到 `######` 以及 Setext 标题均移除 Markdown 标记，不自动补 `【】`。原文手写的括号保留。
- 标题独占一行，沿用现有转换的段落间距（相邻标题之间单换行）；各级字号与正文一致。通用预览和转图默认加粗，选择平台复制后的预览采用对应平台策略。
- 微信、Windows 钉钉、网页及 Windows 企微输出普通标题；Mac 钉钉、飞书桌面版、Mac 企微、邮件和图片保留标题粗体。
- 只调整标题加粗，正文显式的粗体、斜体、删除线沿用现有能力。标题内显式的斜体、删除线、链接等仍沿用现有解析规则；不额外放大字号。
- 内部文字 run 的 `heading: 1..6` 标识标题，用于出口适配；普通正文没有该标记。目标私有协议只输出其支持的字段。
- 主窗口、托盘和全局转换快捷键共用 Markdown → segments → 平台出口。转图直接使用含粗体的原始 segments，不继承某次平台复制的降级结果。

## 当前能力

“生成”指代码携带对应数据；“自动验证”指测试检查生成、绘制或系统表示；“客户端实测”必须记录客户端粘贴/发送结果。三者分别记录。

| --- | --- | --- | --- | --- | --- |

| 钉钉 / Mac 桌面版 | 原生私有图文 + HTML + 纯文本 | 加粗 | 原生字段携带粗体、斜体、删除线 | 本机 PNG 缓存；表格转 PNG；文字可编辑 | 历史 Electron 版一次混排粘贴通过；当前 Tauri 标题粗体及发送效果待验收 |

| 企微 / 网页、Windows 桌面版 | 有图时分段：纯文字和独立 PNG；无图时标准 HTML + 纯文本 | 普通 | 分段文字为纯文本；无图 HTML 可携带正文强调，不保证保留 | 图片逐段粘贴；表格转 PNG；文字可编辑 | 有历史 Mac 分段证据；Windows 真机待验收；不能用 Mac 历史结果替代 Windows 结果 |
| 邮件 / 网页、Mac、Windows | 标准 HTML + 纯文本；粘贴到邮件编辑器 | 加粗 | HTML 粗体、斜体、删除线 | 表格保留可编辑 HTML 单元格；代码、公式、图表仍是图片 | 生成结构已验证；编辑器粘贴、发送后内嵌图片及收件效果待验收，尚无 CID 附件方案 |

| 钉钉、飞书、图片 / 网页 | 入口禁用 | 不对用户开放 | — | — | 不能将底层格式生成测试记为网页可用 |

表格以外的代码块、公式、Mermaid 均沿用转图片规则。平台可能选择纯文本回退；回退中的 `[图片]` 不是图片保留的证据。

## 自动回归入口

| 范围 | 测试与检查内容 |
| --- | --- |
| 平台策略共同基准 | `tests/fixtures/heading-capabilities.json`：网页、Mac、Windows × 六种目标共 18 个组合；`available` 仅表示界面入口开放，不表示客户端验收通过 |
| JS 完整链路 | `tests/headings.test.cjs`：六级/Setext/嵌套标题、手写括号、正文粗体、图文顺序、分段纯文字、托盘/快捷转换回调、复制后平台预览和原始预览隔离 |
| 转图 | `tests/clipboard-image.test.cjs`：解析后的标题绘制为 600 / 20px，正文为 400 / 20px；不注入括号，不改变顺序 |
| 原生输出 | `clipboard::payload::tests::heading_capabilities_match_shared_platform_matrix`：读取相同 JSON 基准，检查 Mac/Windows 的标准 HTML、钉钉私有字段/Cangjie 文字及飞书 fragment |
| Mac 企微 | `clipboard::native::platform::rich::tests` 中的原生富文本回读：字体粗体、中文/emoji、换行、PNG 附件与尺寸；实际测试名见 Cargo 输出 |
| 其他能力 | `tests/targets.test.cjs`、`tests/wecom-export.test.cjs`、`tests/wecom-segments.test.cjs`、`tests/feishu-copy.test.cjs` 及 Rust 原有测试继续覆盖图片、表格、复制路径 |

修改标题策略时同步更新 `assets/chat-targets.js`、`src-tauri/src/clipboard/payload.rs`、共同 JSON 基准及本表。不要为“通过测试”而改写客户端验收状态。

运行 `npm run check` 检查 JS、生成资源及全部 JS 回归；运行 `npm run desktop:test` 检查本机原生层。Mac 上对 Windows 参数生成的 payload 测试属于格式生成测试，不是 Windows 系统剪贴板或客户端测试。

## 客户端验收样本与记录方式

统一使用虚构样本，包含六级标题、正文强调、手写括号、表格、代码和图片。示例输入：

````markdown
# 一级标题

## 二级标题

### 三级标题

#### 四级标题

##### 五级标题

###### 六级标题

## 【手写括号】

普通正文，**正文加粗**、*斜体*、~~删除线~~。

| 项目 | 状态 |
| --- | --- |
| 虚构功能 | 完成 |

```js
const example = "仅测试";
```

尾文：确认图片前后顺序。
````

需要独立原图时，在表格前后再粘贴两张虚构 PNG。分别测试纯文字和有图内容；主窗口、托盘、全局快捷键各记录一次。仅在明确授权后发送测试消息，否则记录为“输入框粘贴”，发送后效果填“未测”。

每次测试在下方追加记录，并更新能力表对应项。失败也要保留，不覆盖历史结果。

| 日期 | 系统/架构 | md2chat 版本/提交及未提交状态 | 客户端版本/输入框模式 | 入口和样本 | 标题/正文强调 | 图片顺序/文字可编辑 | 输入框/发送后 | 证据与结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | — | — | — | — | — | — | — | 不把未执行记为通过 |
