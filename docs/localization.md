# 多语言维护规范

界面、内置示例、官网与指南、README、更新摘要统一支持 `zh-CN`、`en`、`es`、`pt-BR`、`ja`、`ko`、`de`、`fr`、`hi`。新增或修改这些内容时，在同一个改动中同步九种语言，保留相同事实、限制和操作含义。翻译由开发阶段编写和审阅，运行时按用户语言选择，应用不调用在线翻译。

## 各内容的维护入口

| 内容 | 编辑位置 | 验证 |
| --- | --- | --- |
| 界面及原生提示 | `assets/locales.json`；界面使用现有 i18n API，原生提示使用 `locale::tr` | `node scripts/generate-locales.cjs` 生成 `assets/i18n-data.js`；`npm run check` 检查九语言和占位符一致性，相关界面测试检查文案覆盖 |
| 默认示例 | `assets/demo.js` 和对应词条；指南示例源位于 `scripts/site-copy/` | 示例源码、预览及语言切换回归；用户编辑、粘贴、拖入或清空后停止跟随，撤销不恢复自动替换 |
| 官网及指南 | 中英文的 `scripts/site-home.cjs`、`scripts/site-content*.cjs`；其他语言在 `scripts/site-copy/` | `npm run seo:generate` 生成，`npm run check` 检查九语页面、对应链接、公开示例、资源哈希及 SEO |
| README | 根 `README.md` 为中文；其余八语在 `docs/readme/` | 每份保留语言导航及来源哈希；主 README 更新后检查会要求复核全部译文，见下文 |
| 更新摘要和必要提醒 | `docs/releases/<主.次>/<版本>.json`，由统一准备命令维护 | [更新摘要规则](update-summaries.md)；准备、检查、发布前校验九语、历史和长度 |

新增用户可见文案先补齐词条，避免写入界面后只保留中文。动态文案使用命名占位符而不是拼接已翻译的句子。用户输入、粘贴样本、转换结果及详细技术记录保持原内容，只有仍未编辑的内置示例随语言切换。

## README 同步

八语 README 包含产品、安装、平台限制、托盘、语言与更新、隐私、开发及发布说明，并链接详细技术记录；技术记录可保留原文。修改根 README 后，逐份同步受影响内容、检查相对链接，完成一份的人工复核后运行：

```sh
node scripts/check-readmes.cjs --stamp en
```

将 `en` 换为已复核语言；八份全部完成后运行 `npm run check`。来源哈希只证明译文已按当前中文版本复核，不证明翻译语义自动正确；不要仅更新哈希而跳过内容同步。`node scripts/check-readmes.cjs` 可单独检查完整性、导航、相对链接和同步状态。

## 目录与公开网址

仓库内其他八种语言的生成页面集中在 `site/locales/<语言目录>/`。中文页面继续位于根目录与 `guides/`。`scripts/site-locales.cjs` 的 `sourcePath()` 把公开路径映射到源码位置，生成器、预览服务器和构建脚本共用该映射。

公开网址保留 `/en/`、`/es/`、`/pt-br/`、`/ja/`、`/ko/`、`/de/`、`/fr/`、`/hi/`，构建产物仍在 `dist/` 对应路径。canonical、hreflang、站点地图及历史分享链接继续使用原网址。新增语言时更新统一语言和路由表，不在根目录另建语言源码目录。

## 完成条件

1. 九语文案与事实同步；新控件补充相应界面词条覆盖和交互验证。
2. 重新生成语言包和受影响的官网文件；README 来源标记在译文复核后更新。
3. `npm run check` 和 `npm run build` 通过。修改原生提示或更新桥接时，执行本机原生编译/回归。
4. 区分自动化、浏览器验证、真实聊天客户端及安装升级结果。未执行的客户端或升级验收保持待验证。
