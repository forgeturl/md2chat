# 兼容性与证据范围

当前源码使用 Tauri 2。下文注明 Electron 的记录属于历史版本证据，目标客户端的粘贴和发送结果需在 Tauri 版重新验收。

各平台的当前输出策略、标题与强调能力、自动测试入口及客户端验收状态统一记录于 [平台能力矩阵与验证记录](platform-capabilities.md)。调整适配或完成客户端测试后，请同步更新该文档的对应行和验证记录。

## 2026-10-17 Tauri 迁移验证

- macOS 15.7.4 Intel 本机：Rust 单元测试、JavaScript 回归及 Clippy 静态检查通过；旧 Electron 运行代码与专用测试已移除，前端、Tauri 桥接和发布流程验证继续保留。
- 显式原生剪贴板测试通过，确认纯文字、HTML、PNG、钉钉和飞书原生表示可写入并读回；测试恢复原剪贴板。这是系统传输证据，不是客户端粘贴证据。
- 直接运行通用包中的应用二进制，隐藏的真实 WKWebView 通过表格、代码、公式、Mermaid、后台转换保留编辑器内容，以及命令窗口隔离共 6 项检查。可用 `npm run desktop:test:render` 重跑渲染测试，虚构图片和报告写入 `release/qa/`。
- Mac 通用 DMG 为 14,939,583 字节，应用二进制含 `arm64` 与 `x86_64`；本次仅在 Intel Mac 运行。测试包使用本地临时签名，未公证，未正式发布。
- Windows 原生剪贴板核心的跨目标类型检查通过；完整 Tauri 构建被本机缺少 Windows SDK/CRT 阻塞，Windows 安装、运行和聊天客户端粘贴尚未验收。Apple Silicon 运行和所有 Tauri 客户端粘贴也需分别验收。

## 纯前端版本

| 能力 | 范围 |
| --- | --- |
| 解析、预览、表格转 PNG | 在浏览器内完成 |
| 本地图片 | 通过用户粘贴获得，浏览器内解码 |
| 远程图片 | 默认自动加载，依赖图片来源的 CORS 与访问权限 |
| 复制 | 默认标准 `text/html` 与 `text/plain`；企微有图时分段复制纯文字或独立 PNG，浏览器需允许剪贴板写入 |
| 聊天框图文混排 | 企微采用逐段粘贴，证据见下文；其他系统、浏览器和客户端需分别验证 |
| 排查 | 采集浏览器可见格式的原始内容并导出 ZIP；私有格式需桌面版 |

建议在 HTTPS 或 localhost 页面使用。直接双击 file URL 可能遇到权限差异。无 Async Clipboard API 时，尝试浏览器原生 copy 事件；失败会明确提示，不会把静默丢图当成成功。

## 已知问题

- 一次 macOS 钉钉来源样本的浏览器粘贴事件提供了 `text/plain` 和 `text/html`；HTML 含远程图片引用，但没有独立图片数据，浏览器读取失败。没有据此确定是跨域、权限还是网络问题，也没有泛化到所有钉钉版本。样本正文、地址和截图未纳入仓库。
- 桌面版使用 macOS 原生剪贴板，网页仍使用浏览器 API；二者兼容性证据分别记录。
- 图片在网页中可见，不代表可以读取像素、写入剪贴板或被目标应用保留。每一环都需要独立验证。
- 公式与 Mermaid 转为 PNG；已在内置浏览器检查行内公式、分式、中文流程图与时序图的渲染。目标聊天框是否保留这些图片仍须实测。
- 表格单元格内公式暂保留源码；不支持 TeX 外部扩展、Mermaid 自定义配置和外部资源，含 HTML 标签的图形可能无法导出。
- 代码块转为 GitHub 浅色风格 PNG，保留语法高亮，去掉标题栏和行号；长行折行，长代码分图并标明页序。行内代码保留文字，代码图片不能在目标聊天框直接编辑，标准纯文本副本仍含完整源码。目标聊天框是否保留图片需实测。
- 本工具不提供自动消息发送，也不会调用聊天工具机器人 API。

报告问题时，请使用虚构的“文字 + 两张图片 + 表格”内容，分别记录来源、网页结果和目标粘贴结果。可以使用「剪贴板排查」导出诊断 ZIP。包内保留原始内容，请确认样本适合分享。

## 剪贴板诊断包 v3

- 点击「读取当前剪贴板」，查看文字、图文、图片和其他格式的识别结果，再点击「导出诊断 ZIP」。每次读取替换当前样本，导出仅包含当前展示的内容。需对比来源时，分别读取并导出两个 ZIP。导出成功后提供 GitHub Issue 模板链接，检查原始内容后再手动附上 ZIP；关闭窗口会隐藏引导。桌面版使用保存窗口，网页版通过浏览器下载；导出使用已采集的快照，不重新读取剪贴板。
- `manifest.json` 记录采集时间、应用版本、系统、原始格式名、大小、文件位置及失败原因；`report.txt` 提供摘要和文本预览。`sample-N/` 保留各格式原始字节，并附解码文本、格式化 JSON、HTML 标签和完整属性值；属性中的 JSON（如钉钉图文树）也会解析。Windows 的原始 CF_HTML 封装与 Unicode 文字字节不会被解码结果替换。
- 诊断包包含正文、HTML、图片、链接、路径及私有数据。请使用适合分享的测试消息，确认后手动发给开发者。读取只由点击或粘贴触发，不执行 HTML、不请求引用的图片、不读取链接指向的文件、不自动上传。当前样本仅保留在内存中，关闭窗口或按 Escape 后清空，未完成的读取也不会恢复内容；已导出的文件由用户自行保管或删除。
- 单次采集最多 60 MiB 原始数据、1000 种格式；超限或不可读的格式明确记录。单个格式超过 8 MiB 时保留原始数据并跳过文本／HTML／JSON 解析。二进制私有格式保留字节，可能需要专用工具解析。Windows 的 GDI 等对象句柄无法直接作为字节导出，会列出原因。
- 浏览器只能采集其开放的格式，读取按钮会尝试请求未经清理的 HTML；不支持时回退默认结果并记录。系统私有格式和原生 Windows 封装需用桌面版采集。窗口仅提供读取与导出两个操作，不改写剪贴板。诊断数据用于比较格式，不能单独证明目标聊天软件已接受图文。

## Windows 钉钉兼容现状与验证

用户提供的 Windows 0.6.3 脱敏样本只有 `text/html`，包含两张 HTTPS 图片，图片位于 `article > p > img`；没有独立 PNG 或额外媒体属性。它证明钉钉复制出口能提供这类 HTML，不能证明粘贴入口接受任意 HTTPS 或本机文件图片。

v0.6.4 按上述结构改为仅 HTML、本机 PNG 文件引用。用户反馈钉钉粘贴完全空白；报告确认 HTML 含两张 `file` 图片。这否定了该次兼容尝试的可用性，但仍不能区分 HTML 入口被忽略、本机图片引用受限或其他客户端条件。

- Windows 使用与 Chromium 一致的 CF_HTML 封装，同时保留纯文本回退，避免 HTML 未导入时没有文字。纯文本中的 `[图片]` 仅是占位，不能算图片粘贴成功；钉钉客户端效果仍需真机验证。Mac 钉钉继续使用原生私有格式。
- 「剪贴板排查」当前只提供读取和导出两个操作；原有 HTML 文字测试与重写实验已从用户界面移除。Windows 诊断包保留原始 CF_HTML 字节，便于比较封装、结构和图源，不请求 HTML 引用的图片。
- Windows 钉钉图文现在在 `article[data-clipboard-cangjie]` 中携带 JSON 节点树（`root`、`copyFrom: im-native`），图片使用规范化后的内嵌 PNG，并保留普通 HTML 和纯文本回退。此路径不再依赖本机缓存文件或远程图片地址。Mac 钉钉仍使用原生私有格式和本机缓存。
- 本机排查样本包含两张内嵌图片，保存于上述 JSON 属性中；只统计普通 HTML 的 `<img>` 标签会误报为零张。将该样本仅保留 HTML 重写后，用户确认文字和两张图片仍可正常粘回 Windows 钉钉，说明此样本不依赖 `dingtext` 等附加格式。该结果验证了样本重写，生成的新内容仍需单独验收。
- 本地构建反馈表明，钉钉 JSON 的文字叶节点内嵌 `strong`、`em` 等 HTML 节点会丢失整段带样式的文字，包括标题。现改为直接字符串，优先保留完整文字；钉钉 JSON 中暂不附加未经验证的强调样式，标准 HTML 副本仍保留粗体、斜体与删除线。
- Windows 打包流程已改为 Rust 原生剪贴板读写与 CF_HTML 字节校验；另有独立验证工作流和原生测试日志。它验证应用写入和系统读回，不代替钉钉粘贴验收。完整用例与人工结果模板见 [Windows 验证步骤](windows-clipboard-qa.md)。

历史 Electron 版的依赖源码：[Electron 44.8.0 ClipboardItem](https://github.com/electron/electron/blob/v44.8.0/shell/browser/api/electron_api_clipboard_item.cc#L493-L498) 将 HTML 交给 WriteHTML；其 Chromium 152.0.7977.167 在 [Windows 写入路径](https://github.com/chromium/chromium/blob/152.0.7977.167/ui/base/clipboard/clipboard_win.cc#L1050-L1058)调用 [HtmlToCFHtml](https://github.com/chromium/chromium/blob/152.0.7977.167/ui/base/clipboard/clipboard_util_win.cc#L1256-L1372)，自动生成头部、UTF-8 字节偏移与片段标记。当前 Tauri 版由 Rust 原生层生成 CF_HTML，并测试 UTF-8 字节偏移；不能把解码 HTML 中的 `StartFragment 无` 当成原生封装缺失的证据。

公开资料尚未找到可直接复用并确认解决 Windows 钉钉混排的实现。[Microsoft Clipboard 样例](https://github.com/microsoft/Windows-universal-samples/blob/main/Samples/Clipboard/cs/CopyText.xaml.cs)使用 HTML、纯文本及本地图片 ResourceMap；[Windows HTML Clipboard 规范](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format)定义通用片段格式，不能证明钉钉接受任意本机图片引用。

## 2026-10-20 Mac 企业微信整段图文

- 当前系统剪贴板样本提供 `WWKPrivatePBDataKey` 和 `WWKPrivatePBDataReportKey`，系统表示为动态 UTI。两者均是二进制 plist 中的 NSData 数组，内部 Protobuf 包含按顺序排列的文字、图片、文字；没有标准 HTML 或 PNG。私有消息格式还带账号和消息元数据，原始样本未纳入仓库。
- 同一内容在企微草稿中复制后，`WWKPrivatePBDataKey_Rich` 包含进程内对象标识，不能作为其他应用独立生成内容的通用格式。最小 Protobuf 能保留文字，但自造本机图片引用未被接收。
- Mac 导出改用标准 AppKit 富文本，**同时提供 `public.rtf` 和 `com.apple.flat-rtfd`**，另保留 HTML 和纯文字。RTFD 内嵌完整 PNG，不需要企业微信账号信息、进程指针或远程图片地址。单独 RTFD 在本次测试中未插入内容。
- 格式原型生成的虚构“前文 → 绿色 PNG → 后文”在当前企业微信文件传输助手草稿中一次粘贴成功，四种格式同时存在也通过。
- 新生产代码已通过原生编译和回归测试；隔离的 Mac 调试实例中，点击一次「企微」后粘贴一次，企业微信 5.0.12（70798）完整保留“前文😀 → 表格 PNG → 中间文字 → 代码 PNG → 后文”。在后文输入并删除测试字符确认文字可编辑。没有发送消息，测试草稿已清空，原始剪贴板按字节恢复。
- 原生富文本往返测试覆盖中文、emoji、换行、两张独立 PNG 和显示尺寸。PNG 保存分辨率元数据，既保留高清像素，也使附件恢复后按预期尺寸显示。
- Mac 主窗口、托盘和全局转换快捷键均走同一整段复制路径，写入前保留剪贴板更新检查；网页和 Windows 有图时继续分段。历史分段测试仅说明当时尝试的格式组合，不代表企业微信只能分段。

## 托盘剪贴板快捷转换

## 2026-10-17 macOS 飞书一次混排实测

标准 HTML + 纯文本在当前飞书客户端中只保留文字和强调样式，两张内嵌 PNG 丢失。改为飞书原生编辑 fragment，加标准 HTML 与纯文本后，用户在展开的富文本输入框一次粘贴「前文 + 蓝图 + 中间文字 + 绿图 + 后文」，并提供发送后截图确认顺序、两张图片和粗体、斜体、删除线完整。

Mac 桌面版主窗口与托盘采用该格式，图片使用本机 PNG 缓存及新 UUID，不依赖账号配置。普通输入框可能丢图，必须先展开富文本输入框。此证据限本机客户端；网页版已禁用飞书复制，Windows 飞书仍待验证；客户端产品版本号尚未从关于界面确认。详细用法、格式与自动传输测试见 [Mac 飞书适配](feishu-mac.md)。

## Windows 飞书编辑器样本与适配

在 Windows 飞书 7.51.0.45 中，用户反馈标准 HTML 粘贴仅有文字，图片缺失。消息正文复制只提供 HTML，图片带 `data-lark-image-uri` 等内部引用；从有图的富文本编辑区复制则额外提供 `Chromium Web Custom MIME Data Format`。其 Chromium Pickle 包含 `application/x-editor-kit-business-key = IM_CHAT` 及 `application/x-editor-kit-fragment`，图片位于 `deltas` 的 image 节点中。

Windows 生成路径现复用编辑 fragment 和本机 PNG 缓存，并将应用内部的 `org.chromium.web-custom-data` 名称映射到上述 Windows 原生格式；读取时反向映射，以便识别和保护仍被剪贴板引用的缓存。界面提示先展开飞书富文本输入框。样本中的已上传图片标识不进入生成内容，生成内容使用新 UUID 和本机图片路径。
