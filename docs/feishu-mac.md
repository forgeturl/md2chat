# Mac 飞书一次图文粘贴

在 md2chat Mac 桌面版生成预览，点击「飞书」，再到飞书点击输入框右侧的展开按钮，进入富文本编辑，按 ⌘V 一次粘贴整段。托盘「飞书格式」使用同一转换路径。普通输入框可能过滤图片，必须先展开。

文字保持可编辑，表格、代码、公式和图表沿用现有 PNG 转换。工具只复制，不自动发送，不需要配置飞书账号或机器人；复制用 PNG 缓存在本机。图片在飞书中粘贴后，由飞书客户端按正常流程处理。

## 已验证范围

以下为迁移前 Electron 版的客户端证据，Tauri 版需重新完成粘贴验收。2026-10-17 在本机 macOS 飞书客户端，通过虚构样本完成手工对照：

| 复制内容 | 结果 |
| --- | --- |
| 标准 HTML + 纯文本，HTML 含两张 data URI PNG | 文字和强调样式保留，两张图片丢失 |
| 原生编辑 fragment + HTML + 纯文本，本机 PNG 路径 | 展开的富文本输入框一次粘贴，前文、蓝图、中间文字、绿图、后文顺序正确；粗体、斜体、删除线保留；用户发送后截图确认完整 |

未将私人截图、原始飞书剪贴板、账号标识、图片 token 或客户端安装包纳入仓库。飞书产品版本号未从关于界面确认；该结果不代表所有版本均兼容。网页和 Windows 飞书仍为实验性标准图文，不外推本次 Mac 结果。

## 实现与缓存

Mac 飞书复制在同一个剪贴板 item 中写入标准 `text/html`、`text/plain` 和原生 `org.chromium.web-custom-data`。自定义表示使用 Chromium Pickle 保存两个 UTF-16 字符串键值：

- `application/x-editor-kit-business-key`：`IM_CHAT`。
- `application/x-editor-kit-fragment`：带 `deltas`、`editorUniqueId` 的编辑数据。

fragment 中图片使用新 UUID、`INITIAL` 状态和应用自己生成的 PNG 缓存绝对路径，让飞书按正常图片上传流程处理。不会复用账号 ID、已上传图片 token，或读取飞书账号数据。

成功写入替换上一份剪贴板后才清理超过 7 天的旧缓存；启动时若检测到原生图文相关表示则暂缓清理，保护仍可能被剪贴板引用的图片。HTML 备用副本仍使用内嵌 PNG，网页和 Windows 不获得 Mac 私有格式。

## 自动检查

`npm run desktop:test:feishu` 检查当前 Rust 实现的 Pickle 编码、Unicode 和大小边界，不读写系统剪贴板。`node --test tests/feishu*.test.cjs` 检查前端的飞书复制与操作提示。

`npm run desktop:test:native` 使用当前 Rust 原生剪贴板接口，写入并读回虚构的纯文字、HTML 和 PNG；Mac 另检查钉钉、飞书原生表示。测试结束后恢复原剪贴板；若期间用户复制了新内容，则保留新内容。运行时请暂时不要复制其他内容。此命令只验证系统格式传输，不代表飞书客户端接受整段图文。

历史 Electron 44.8.0 的真实 Mac 剪贴板检查确认了两个图片节点、图文顺序与强调样式，以及原剪贴板恢复和临时缓存删除。上述客户端结果不能直接作为 Tauri 迁移的验收结论。
